# Frontend Design Preview 模板

仅用于 `<doc 组件> tmp frontend req <需求组件> preview`。未指定 `preview` 时不得加载或执行本模板。

示例：

```text
<doc browser> tmp frontend req require preview
- 基于 DESIGN.md 生成首页、商品列表、商品详情和结算表单四个静态页面，只用于确认整体风格
```

## 交付契约

- 只创建或修改 `design-preview/**`；不修改 `DESIGN.md`、Require、README、Draft、资产、Configuration、Testing 或生产代码。
- `design-preview/**` 是可重新生成、可删除的静态风格评审产物，不是页面需求、页面设计或设计系统事实，不作为 Draft、dev 或 test 的输入。
- `DESIGN.md` 是唯一设计事实源。用户对预览提出反馈后，使用显式 `design` 指令修改 DESIGN.md，再重新生成预览；不得把反馈只固化在预览 CSS 中。

## 输入

1. 完整读取并校验当前组件根目录的 `DESIGN.md`；不存在、无法解析或存在影响渲染的 Token 错误时停止。
2. 递归读取显式 Require，选择能代表实际角色、内容密度、控件类型和目标终端的页面类型；只借用业务语境，不复制完整流程或实现真实能力。
3. 只读复用已有品牌资产；没有合适资产时使用 CSS、内联 SVG 或明确占位内容，不创建第二个资产系统。

## 固定结构

按任务要求创建实际需要的页面；默认示例结构为：

```text
design-preview/
├─ index.html
├─ list.html
├─ detail.html
├─ form.html
└─ assets/
   ├─ fonts/
   └─ images/
```

- `index.html` 同时作为第一个代表页面和其他预览页入口。
- 页面文件使用稳定、简短的 kebab-case 名称。每页的 CSS、必要 JavaScript 和 SVG 图标直接内嵌到该 HTML，不生成外部 `.css` 或 `.js` 文件。
- 预览专用的字体和图片统一放在 `design-preview/assets/`，HTML 只使用 `./assets/...` 相对路径；不引用组件根目录外的资源。
- 不引入框架、包管理器、构建工具、CDN、网络 API 或后端。

## 页面规则

- 每个页面只展示足以判断风格的代表性内容和状态，不追求需求完整性或真实业务闭环。
- 忠实使用 DESIGN.md 的颜色、字体、间距、圆角、边框、阴影、层级、动效、组件和响应式规则；禁止在预览中建立第二套 Token。
- 项目指定内置中文字体时，收集全部预览页的可见文字并生成一份共享 WOFF2 字符子集；文字变化后必须重建子集并检查缺字，不得为方便直接打包完整中文字体。
- 字体必须具有再分发许可并提供中文系统字体回退；不打包苹方、微软雅黑等系统商业字体。缺少可授权源字体或子集工具时，暂停该决定并通过对话获取，不得换成完整字体。
- 优先将支持 `wght` 轴的可变字体子集为单个文件，通过 `font-weight: 100 900` 提供真实的 400、500、600、700 字重；不支持时才分别子集化这四个字重。页面设置 `font-synthesis: none`，不得用 Regular 模拟粗体。
- 覆盖导航、标题层级、主要操作、表单、列表或表格、卡片、反馈状态等与任务相关的视觉组合。
- 使用明显的模拟数据，不连接真实服务，不保存用户输入，不展示真实个人或敏感信息。
- 页面顶部或元信息明确标注“Design Preview — 非产品页面”。
- 不复制 `design-preview/**` 的 HTML、CSS 或 JavaScript 到 `draft/**`；正式页面设计必须重新读取 Require 与 DESIGN.md。

## 浏览器验证

1. 先通过 `file://` 直接打开全部页面，检查链接、资源、控制台和主要交互；浏览器不支持本地文件时才使用本地 HTTP 服务并说明限制。
2. 在 DESIGN.md 规定的代表视口检查溢出、裁切、内容密度、字体加载与字重、字体替换布局偏移、对比度、焦点和响应式变化。
3. 支持图片理解时检查并比较全部页面截图，报告风格一致性和明显问题；不支持图片时只能报告结构、样式加载与交互检查结果。
4. 未实际执行的浏览器、截图、视觉或可访问性验证不得声明为通过。

## 完成检查

- 页面数量和类型满足任务正文，且足以判断整体风格，不额外搭建组件文档站或应用框架。
- 所有页面只消费 DESIGN.md，没有反向修改或覆盖它；各 HTML 内嵌样式没有未说明的设计值分叉。
- 直接打开 HTML 时不依赖网络、外部 CSS/JavaScript 或 `design-preview/` 之外的资源。
- 字体子集覆盖所有预览页可见文字，没有缺字、完整中文字体、合成字重或可见的字体替换跳动。
- 只修改了 `design-preview/**`，没有触碰 Draft 或生产文件。
- 最终回复列出页面入口、使用的 DESIGN.md 范围、实际验证、发现的设计问题，并明确后续反馈应通过 `design` 指令更新 DESIGN.md。
