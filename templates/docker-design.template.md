# Docker 文档模板

用于 `<doc 组件> tmp docker`。只维护 `docs/<组件>/README.md`；实际 Compose、Dockerfile、配置和脚本属于
仓库根目录 `docker/<组件>/**`，由 `<docker 组件>` 维护。

## 专家团

- 容器架构专家：负责镜像、服务边界、依赖、网络、端口和健康检查。
- 数据与安全专家：负责卷、数据生命周期、配置、密钥、权限和供应链风险。
- 运维与恢复专家：负责启动顺序、资源约束、观测、备份、升级、回滚和恢复。

专家只读分析并返回决策、风险、建议和阻塞；主 Agent 统一修改与验证。

- README 是该组件容器编排文档的唯一文件，不创建其他 Docker 设计文档。
- 服务名必须稳定，并与 `docker/<组件>/` 中实际编排一致。
- 镜像版本来自已确认的官方来源或仓库事实，不猜测、不使用 `latest` 或版本范围。
- 纯 Docker 组件不声明应用目录或开发模板；同时包含业务源码的组件保留已有 Frontend/Backend 声明。
- 文档定义结果、边界和可验证约束，不复制完整 Compose、Dockerfile 或脚本。
- 依赖必须说明启动条件，不能只写服务名；健康检查验证服务可用性，不只验证进程存在。
- 端口默认不暴露到宿主；确需暴露时说明访问方和用途。网络按最小通信范围划分。
- 卷明确数据所有者、持久化、备份和恢复要求；无状态服务不创建无意义持久卷。
- 配置只记录名称和来源，不记录真实密钥值。敏感值必须从外部安全注入。
- 只有存在真实容量边界时填写资源值；不能核实的版本、端口、命令或限制必须标记待确认，不得猜测。

## 完成检查

- README 的组件职责、Docker 目录、服务名、镜像和版本来源真实且唯一。
- 服务依赖、健康检查、端口、网络、数据、配置、升级和恢复覆盖当前风险。
- 没有创建其他 Docker 设计文档，没有复制 Compose YAML，也没有写入凭据、单次运行状态或未经确认的环境值。
