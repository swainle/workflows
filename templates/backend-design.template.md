# Backend 文档模板

用于 `<doc 组件> tmp backend`。先创建或读取 README 的技术入口，再按已确认的业务复杂度选择最小模式。

## 专家团

- 领域与 API 专家：负责模型、业务规则、接口、错误和契约映射。
- 数据与安全专家：负责数据所有权、一致性、认证、授权和敏感信息。
- 可靠性与测试专家：负责任务、幂等、恢复、可观测性、性能和验证策略。

专家只读分析并返回决策、风险、建议和阻塞；主 Agent 统一修改与验证。

## 模式

轻量模式适用于简单 CRUD 或适配器：没有需要独立表达的不变量、状态机、领域事件、跨聚合一致性、
复杂授权或后台任务。创建 README、`interface.md` 和 `engineering.md`。

出现任一上述信号时使用完整模式，并按需增加 `domain.md`、`security.md`、`data.md`、`jobs.md`、
`operations.md` 及机器契约。不要因为模板出现某种技术就采用它。

## 依赖顺序

```text
README.md 技术入口 + 显式 req
  ├─ domain.md ─┬─ interface.md ── engineering.md ─┬─ jobs.md
  │             ├─ security.md                    └─ operations.md
  │             └─ data.md
  └─ OpenAPI/其他上游契约
                                    └─ README.md 索引与文件树校对
```

README 第一个创建或确认，先提供后续设计需要的技术事实；其他设计完成后只校对文档索引、文件关系、
架构概览和完整应用文件树，不重新选择技术。

- 技术基线只列当前组件实际采用的语言、运行时、框架及必要基础库；数据库、队列、授权、测试等实际使用时再增加行。

## 文件职责

| 文件 | 唯一维护内容 |
|---|---|
| `domain.md` | 限界上下文、统一语言、模型、业务规则、事件、状态和一致性 |
| `interface.md` | 上游契约映射、组件接口、错误和事务边界 |
| `security.md` | 当前组件的认证、授权、敏感数据和威胁落实 |
| `data.md` | 数据所有权、生命周期、迁移和一致性策略 |
| `engineering.md` | 代码分层、模块、依赖方向及 README 技术基线的实现约束 |
| `jobs.md` | 后台任务、调度、重试、幂等、死信和补偿 |
| `operations.md` | 配置、健康检查、遥测、容量、降级与恢复要求 |
| `openapi.json`、`asyncapi.json`、`schema.dbml`、`authorization.fga` | 对应机器可读事实 |

机器契约属于实际提供该事实的文档组件。`interface.md` 只映射上游同步 HTTP 契约，不复制 Schema；
缺少操作、错误或示例时返回契约所有者。组件私有异步、数据或授权契约仅在需要时创建。

## 表达规则

- Markdown 最多三级标题。稳定引用为 `<文件名>:<二级标题>:<三级标题或三位编号>`；找不到更深项时停在已有层级。
- 引用使用独立行 `> Ref: <标识>`。生产主实现使用 `@design <标识>`，其他实现使用
  `@design-ref <标识>`，测试使用 `@verifies <标识>`。
- 领域层不依赖 HTTP、框架、ORM、JWT、授权引擎或消息队列。跨聚合只持有聚合根稳定 ID。
- 同步调用明确超时、重试和幂等；写操作明确事务边界；异步处理明确投递、去重、重试和补偿。
- 数据字段和约束属于机器契约，不在多份 Markdown 重复维护。

## 完成检查

- 模式选择有实际复杂度依据，只创建需要的文件。
- README 在其他设计前建立，应用目录、`backend` 模板、实际版本、官方文档和范例代码完整可用。
- 需求、领域、接口、数据、工程、任务和运维依赖单向且引用可解析。
- 安全、事务、一致性、失败恢复和可观测性覆盖当前风险，没有复制全局或上游事实。
- README 的技术选择没有在其他文件重复维护，最终索引和完整文件树已校对；代码标识能由现有验证器解析。
