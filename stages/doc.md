# `<doc 组件>` 文档组件

## 职责

维护 `docs/<组件>/**` 中长期有效的需求、规范、契约与设计。组件入口是 `README.md`；
跨组件事实使用稳定路径或标识引用，不复制维护。源码、测试和部署不属于本阶段。

## 权限

| 路径 | 创建 | 读取 | 修改 | 删除 |
|---|---|---|---|---|
| `**` | 禁止 | 禁止 | 禁止 | 禁止 |
| `docs/*/README.md` | 禁止 | 允许 | 禁止 | 禁止 |
| `docs/<当前组件>/**` | 允许 | 允许 | 允许 | 允许 |
| `docs/<req组件>/*` | 禁止 | 允许 | 禁止 | 禁止 |
| `docs/<req组件>/REQ-<指定编号>-*/**` | 禁止 | 允许 | 禁止 | 禁止 |

`docs/workflows/**` 不是组件内容。没有 `req` 时不得读取其他组件正文。删除仍需用户明确要求。

## README

每个组件必须有 `docs/<组件>/README.md`，至少说明名称、职责和文档索引。
非纯文档组件还必须声明：

```md
应用目录：`apps/<实际路径>/`
开发模板：`backend`
```

路径必须是仓库相对目录、以 `/` 结尾、不含 `..`，且一个组件只能声明一个应用目录。
开发模板按实际组件改为 `frontend` 或 `backend`，且只能声明一个。纯文档组件不写这两行。

## 参数

- `issue <编号>`：没有 `req` 时完整执行 `templates/issue.template.md`，写当前组件的对应
  `REQ-*` 目录；组件不存在时同时创建最小 README。
- `tmp arch|frontend|backend`：完整执行对应模板；模板只增强本阶段，不扩大权限。
- `tmp arch issue <编号>`：同时维护当前组件根目录的全局设计和对应 `REQ-*` 需求，两份模板都必须加载。
- `req <组件>`：根文件指该组件目录直属文件，不包含任何子目录；`issue <编号>` 只追加匹配的
  `REQ-*` 子目录。找不到或匹配多个目录时停止。
- `opt <文件>`：只创建或修改该文件。目标通常相对当前组件目录；仅使用 Issue 模板时相对目标
  `REQ-*` 目录；`tmp arch issue` 组合时仍相对组件根目录，需要修改需求文件则写出 `REQ-*` 相对路径。
  使用 `opt` 时当前组件 README 必须已经存在，除非唯一目标就是 `README.md`。

## 通用规则

- 一个事实只有一个所有者；契约本体由提供方维护，消费方只引用。
- 只创建当前任务需要的文件，不为模板完整性创建空文档、空图或占位章节。
- 图仅在关系或时序比文字更清楚时使用；目录树必须完整，不使用省略号或通配符。
- 同步 HTTP 契约使用 OpenAPI，异步契约使用 AsyncAPI；文件属于实际提供该事实的文档组件。
- 发现需求、边界或映射冲突时先确认，不用设计决定掩盖冲突。

## 执行

1. 解析当前组件；按需创建目录和 README，或验证现有 README。
2. 只加载显式 `req` 指定的根文件与 Issue，以及当前任务选择的 Arch、Frontend、Backend 或 Issue 模板。
3. 检查现有事实、引用和用户修改，确认会改变结果的歧义。
4. 增量修改当前组件；`opt` 时仅修改目标文件。
5. 检查链接、契约语法、应用目录和目录树；运行 `node docs/workflows/validate.mjs`。

## 完成检查

- 修改只在当前文档组件内，且 `opt` 没有触及第二个文件。
- README 存在；非纯文档组件的应用目录唯一、有效且未猜测。
- 显式引用的需求与稳定标识存在，没有复制其他组件所有的事实。
- 没有写入源码、测试、部署文件或过程记录。
