# `<dev 组件>` 开发

## 职责

根据 `docs/<组件>/**` 实现映射应用目录中的生产代码。行为、契约或设计不明确时返回
`<doc 组件>`，不得用实现反向改写文档。

## 权限

| 路径 | 创建 | 读取 | 修改 | 删除 |
|---|---|---|---|---|
| `**` | 禁止 | 禁止 | 禁止 | 禁止 |
| `docs/<组件>/**` | 禁止 | 允许 | 禁止 | 禁止 |
| `docs/<README 引用的 req 组件>/**` | 禁止 | 允许 | 禁止 | 禁止 |
| `<映射应用目录>/**` | 允许 | 允许 | 允许 | 允许 |
| `<映射应用目录>/test/**` | 禁止 | 禁止 | 禁止 | 禁止 |

项目清单、锁文件及应用目录内的构建配置属于生产实现，可按实际需要修改；真实凭据除外。

## 执行

1. 从 README 解析应用目录、唯一 `开发模板` 和第一条 Require 引用，加载 Frontend 或 Backend 模板中的专家团与技术基线规则。
   Frontend 读取 Require、`DESIGN.md`、`draft/**`、`configuration.md` 和 `testing.md`；QML Draft 是可观察界面与交互的转换输入，不是生产依赖，页面 `index.html` 只是设计参考；不得读取或转换 `design-preview/**`。
2. 专家只读评审设计、实现风险和验证方式；主 Agent 汇总结论。
3. 建立“需求或稳定 Draft 标识 → 实现位置”映射；Frontend 按 `M-001/LAYOUT-001/View.qml`、
   `M-001/P-001/View.qml` 和 `M-001/P-001/COMP-001/View.qml` 转换到目标平台，不要求独立 `mapping.md`。
   实现 BR 的 `REQUIRES PERMISSION` 前，确认权限已在 PERM 表登记。
4. 复用现有结构和依赖，以最小改动实现任务；不创建测试或过程文档。
5. `opt` 时只创建或修改应用目录内的唯一目标文件。
6. 运行最小静态检查、构建或现有验证；失败必须如实报告。

## 完成检查

- 修改只在映射应用目录，未触碰测试目录或组件文档。
- 实现符合已确认的行为、契约、安全、数据与兼容性约束。
- Frontend 生产代码与 QML Draft 的页面、组件、布局、状态、事件、动画、响应式和主题表现一致；临时 Mock 已按 `configuration.md` 替换或明确保留边界。
- 没有增加无必要抽象、依赖、配置或重复契约。
