# `<test 组件>` 组件测试

## 职责

在组件映射应用目录的测试目录中实现并执行单元、集成、接口、契约、权限、并发或组件级端到端测试。
跨组件用户旅程属于全局 `<test>`，生产修复属于 `<dev 组件>`。

## 权限

| 路径 | 创建 | 读取 | 修改 | 删除 |
|---|---|---|---|---|
| `**` | 禁止 | 禁止 | 禁止 | 禁止 |
| `docs/<组件>/**` | 禁止 | 允许 | 禁止 | 禁止 |
| `<映射应用目录>/**` | 禁止 | 允许 | 禁止 | 禁止 |
| `<映射应用目录>/test/**` | 允许 | 允许 | 允许 | 允许 |

若项目明确使用其他测试目录，以 README 或现有项目配置中的唯一实际目录替代 `test/**`。

## 执行

1. 从 README 解析应用目录和唯一 `开发模板`，加载 Frontend 或 Backend 模板中的专家团与测试规则。
2. 专家只读评审覆盖范围、风险和测试层级；主 Agent 汇总结论。
3. 选择能在最低层稳定证明行为的测试；不重复测试框架、生产算法或契约模型。
4. `opt` 时只创建或修改测试目录内的唯一目标文件。
5. 先运行新增或修改的测试，再按影响运行相关套件；不默认运行无关全量检查或生成报告。
6. 生产缺陷导致失败时保留有效断言并报告，不在本阶段修改生产代码。

## 完成检查

- 修改只在组件测试目录，测试关联真实需求或设计且断言可观察结果。
- 外部依赖隔离符合现有项目方式，没有访问生产服务或真实凭据。
- 通过、失败、跳过和未执行结果均如实说明。
